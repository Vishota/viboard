# Правила для агентов — tasks (файловая доска)

Версия: 1.0 · 2026-11-20 · Владелец правил: владелец проекта. Обязателен к прочтению каждым агентом (менеджером, исполнителем, проверяющим, ассистентом) перед работой.

## 1. Роли файлов и приоритет

| Файл/каталог | Роль | Статус |
|---|---|---|
| `spec.md` | Канон: единственный источник нормативной истины по протоколу доски | всегда актуален |
| `decisions.md` | Журнал решений владельца: дословно, UD-N | всегда актуален |
| `agents.md` | Настоящие правила (процесс) | всегда актуален |
| `current/` | Разборы, планы, отчёты, open-questions | актуально |
| `archive/` | Старые версии канона. Только чтение, нормативной силы не имеют | история |
| `board/` | Живая доска — **данные, не документация**; регулируется spec.md | всегда актуальна |
| `tools/` | vistamp (spec §11) и будущие инструменты | — |

Приоритет: spec > decisions > current > archive. Противоречие архива канону гасится каноном.

## 2. Полномочия агента (градуированная автономия)

| Уровень | Действие агента | Критерий |
|---|---|---|
| Сам, в текст работы | win-win правки, вытекающие из принятых решений/аксиом | очевидное улучшение, ничего не ломает, семантику протокола не меняет |
| Сам + доклад в следующем сообщении | низкая цена + явный выигрыш; помечать в decisions «принято по правилу автономии» | оба условия явные |
| Только владелец | семантика протокола, новые сущности, необратимое | пакетом вопросов с рекомендацией |

Мандат упрощения: при каждом изменении канона искать упрощения (удаление сущностей/полей/правил, слияние); усложнение — только через вопрос. Замалчивание сомнений запрещено: несогласие проговаривается явно, отдельно от исполнения.

## 3. Протокол сессии

1. Решения владельца — немедленно в `decisions.md`, дословно, с датой; применение — после фиксации.
2. Вопросы владельцу — обычным текстом (не интерактивные опросы), самодостаточные, с вариантами, последствиями и рекомендацией; копятся и отдаются пакетом. Для асинхронных вопросов — механизм spec §8.
3. Промежуточные результаты и формулировки из чата копируются в файлы той же сессией — сжатие контекста не должно иметь возможности их убить.
4. Процессуальные указания владельца → в этот файл со ссылкой на UD-N; продуктовые → в decisions.
5. Коммиты: доску коммитит только менеджер на проходе (spec §10.9, N8); изменения канона/инструментов — отдельно от данных доски, сообщение-биография со ссылками UD-*/N*.

## 4. Версионирование канона

1. Нормативное изменение spec.md = новая версия; перед изменением текущая копируется в `archive/` (снапшот «как было»). Архив не редактируется никогда.
2. Канон самодостаточен; одному механизму — одно имя (глоссарий §1).
3. Каждая правка помечается тегом-источником: `UD-*` (решение владельца) или `N*` (находка разбора/волны).
4. История изменений — в git-коммитах-биографиях; отдельный changelog-файл не ведётся (мандат упрощения).

## 5. Кто что меняет

| Роль | spec/agents | decisions | карточки | board/log, log карточек | current |
|---|---|---|---|---|---|
| ассистент сессии | черновик в current/ | фиксирует дословно | как исполнитель по spec | по spec §7 | да |
| агент-исполнитель | нет | нет | свою залоченную | по spec §7 | да |
| проверяющий | нет | нет | вердикт + mv по spec §5 | вердикт | да |
| менеджер | нет | нет | assignee + mv по spec §5, §10 | нет (кроме валидации имён) | да |

## 6. Экономия токенов

spec §12 + method §8: скоупированные проверки, ls перед read, точечное чтение, короткие записи; промежуточные раунды — на дешёвой модели; канон краток.

## 7. Красные линии

- Тело карточки и `answer.md` — пишет только владелец; агент/менеджер не редактируют (А3). Вместо правки — вопрос или новая запись в лог.
- Карточку в doing/ трогает только держатель её лока (А7).
- Доску коммитит только менеджер (N8).
- Постановки LLM не пишет (А3); непонятная карточка возвращается вопросом, не дописыванием.
- Время, имена записей, номера id — только через vistamp (А4); руками не набирать.
- decisions.md — дословно и без перенумерации, никогда.
